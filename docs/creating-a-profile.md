# Tutorial: create your own Forge profile

This guide walks through adding a **custom profile** so `forge new -p <name>`
scaffolds projects your way.

Profiles are directories under `profiles/<name>/`. Forge loads them at runtime
(editable install or `FORGE_PROFILES_DIR`).

---

## 1. Mental model

```text
profiles/my-profile/
├── profile.toml      # name, description, inheritance, wizard variables
├── structure.toml    # directories + file map + conditionals
└── templates/        # Jinja2 sources (*.j2)
```

**Inheritance:** a child profile can set `inherits = "base"` (or another
profile). Forge merges **parent then child**:

- **Variables:** child keys override parent  
- **Directories:** union (order preserved, no dups)  
- **Files / conditionals:** child keys override parent  
- **Templates:** child `templates/` searched **before** parent (override a
  parent file by using the same template filename)

Built-in chain today:

```text
base  ←  fullstack
```

You almost always want:

```toml
inherits = "base"
```

so you only add deltas.

---

## 2. Where to put it

### A. Contribute upstream (this repo)

```bash
cd /path/to/nebulus-forge
mkdir -p profiles/my-profile/templates
# create profile.toml, structure.toml, templates…
forge profiles list   # should show my-profile
```

Requires an **editable** install so Forge sees the repo `profiles/` tree:

```bash
pipx install --force --editable /path/to/nebulus-forge
# or: pip install -e .
```

### B. Private / org profiles (recommended for company flavor)

Keep custom profiles **outside** the public package:

```bash
mkdir -p ~/forge-profiles/my-profile/templates
export FORGE_PROFILES_DIR=~/forge-profiles
# Copy or symlink base if you need inheritance from public base:
# Option 1: set FORGE_PROFILES_DIR to a tree that contains both base + my-profile
# Option 2: put your profile in the clone under profiles/ and don’t push it
```

`FORGE_PROFILES_DIR` must be a directory that **contains** profile subfolders
(including `base` if you inherit it). Practical pattern:

```bash
# Work in a clone; add private profile locally (gitignored) or use a fork
export FORGE_PROFILES_DIR=/path/to/nebulus-forge/profiles
```

## 3. Minimal profile (no inheritance)

Good for learning; production profiles should inherit `base`.

### `profiles/hello/profile.toml`

```toml
[profile]
name = "hello"
description = "Minimal hello-world profile (tutorial)"

[variables]
[variables.project_name]
prompt = "Project name"
type = "string"

[variables.greeting]
prompt = "Greeting line"
type = "string"
default = "Hello from Forge"
```

### `profiles/hello/structure.toml`

```toml
[directories]
root = [
    "src",
    "docs",
]

[files]
"README.md" = "README.md.j2"
"src/.gitkeep" = "gitkeep.j2"
```

### `profiles/hello/templates/README.md.j2`

```jinja2
# {{ project_name }}

{{ greeting }}

Generated by the **hello** Forge profile.
```

### `profiles/hello/templates/gitkeep.j2`

```jinja2
```

(Empty file is fine.)

### Try it

```bash
forge profiles list
forge profiles show hello

forge new /tmp/hello-demo -p hello --no-interactive \
  --var project_name=hello-demo

cat /tmp/hello-demo/README.md
```

Non-interactive runs apply **defaults** from `profile.toml` for any missing
`--var`. `project_name` defaults to the **target directory name** if omitted.

## 4. Recommended: extend `base`

### `profiles/api-service/profile.toml`

```toml
[profile]
name = "api-service"
inherits = "base"
description = "HTTP API service on top of base (tutorial example)"

[variables]
[variables.http_port]
prompt = "HTTP listen port"
type = "string"
default = "8080"

[variables.include_openapi]
prompt = "Include OpenAPI stub?"
type = "confirm"
default = true
```

### `profiles/api-service/structure.toml`

```toml
[directories]
root = [
    "src/{{ project_slug }}/api",
    "deploy",
]

[files]
"src/{{ project_slug }}/api/__init__.py" = "api_init.py.j2"
"deploy/README.md" = "deploy_readme.md.j2"
"openapi.yaml" = "openapi.yaml.j2"

[conditionals]
"openapi.yaml" = "include_openapi"
```

Notes:

- `{{ project_slug }}` is derived from `project_name` (lowercased, spaces/hyphens → `_`).
- **Conditionals** map an **output path** → a **boolean variable name**.  
  If that variable is falsy, the file is skipped.
- You do **not** re-list base files; inheritance merges them.

### Example templates

`templates/api_init.py.j2`:

```jinja2
"""HTTP API package for {{ project_name }}."""

DEFAULT_PORT = {{ http_port }}
```

`templates/deploy_readme.md.j2`:

```jinja2
# Deploy {{ project_name }}

Default port: `{{ http_port }}`
```

`templates/openapi.yaml.j2`:

```jinja2
openapi: 3.0.3
info:
  title: {{ project_name }}
  version: 0.1.0
paths: {}
```

### Generate

```bash
forge new ~/projects/billing-api -p api-service --no-interactive \
  --var project_name=billing-api \
  --var http_port=9090 \
  --var include_openapi=true
```

You get **all of base** (tests, docs, AGENTS.md, hooks, …) **plus** api/deploy files.

## 5. Variable types (`profile.toml`)

| `type` | Wizard UI | `default` | Example |
|--------|-----------|-----------|---------|
| `string` | text input | optional string | `"my-app"` |
| `choice` | select | one of `choices` | `python_version` |
| `confirm` | yes/no | `true` / `false` | `use_docker` |

```toml
[variables.use_redis]
prompt = "Include Redis?"
type = "confirm"
default = false

[variables.runtime]
prompt = "Runtime"
type = "choice"
choices = ["local", "docker"]
default = "local"
```

CLI:

```bash
forge new ./app -p api-service --no-interactive \
  --var project_name=app \
  --var use_redis=true \
  --var runtime=docker
```

Boolean-like `--var` values: `true`/`yes`/`1` or `false`/`no`/`0`.

### Built-in derived flags

Forge also sets (you usually don’t pass these):

| Key | Meaning |
|-----|---------|
| `project_slug` | From `project_name` |
| `use_pip` | `true` when `manager == "pip"` (base conditionals) |
| `use_docker` | Defaults `true` if unset (fullstack Docker files) |

## 6. Conditionals and optional files

In `structure.toml`:

```toml
[conditionals]
"Dockerfile" = "use_docker"
"docker-compose.yml" = "use_docker"
```

The left key is the **output path** (as in `[files]`).  
The right value is a **variable name** that must be truthy.

Use this for optional OpenAPI, Docker, CI extras, etc.

---

## 7. Overriding a parent template

To replace base’s `README.md` in your profile:

1. Keep `"README.md" = "README.md.j2"` in **your** `structure.toml` **or** rely on base’s mapping (same template name is enough if the file is only defined on base — to override content, put `README.md.j2` in **your** `templates/`).
2. Because child template dirs are searched first, your `templates/README.md.j2` wins.

You do not need to re-declare the file in `structure.toml` if the parent already maps `README.md` → `README.md.j2`; providing the template file in the child is enough for content override. If you add a **new** output path, declare it under `[files]`.

## 8. Directories only

```toml
[directories]
root = [
    "migrations",
    "configs/{{ project_slug }}",
]
```

Jinja in directory names is supported (`{{ project_slug }}`).

Empty dirs are created even if no files are written into them.

---

## 9. Checklist before you share a profile

- [ ] `profile.toml` `name` matches the directory name  
- [ ] Prefer `inherits = "base"` unless you have a strong reason not to  
- [ ] Every `[files]` value exists under `templates/` (or a parent template dir)  
- [ ] Conditionals reference real boolean variables with defaults  
- [ ] `forge new /tmp/probe -p <name> --no-interactive --dry-run` succeeds  
- [ ] No secrets, private hosts, or org-only paths in templates  
- [ ] Document the profile in your README or internal wiki

## 10. Debugging

| Symptom | Fix |
|---------|-----|
| Profile not listed | Editable install? `FORGE_PROFILES_DIR`? Missing `profile.toml`? |
| `Template 'x.j2' not found` | Filename mismatch vs `[files]` value; check inheritance template dirs |
| Jinja `UndefinedError` | Missing variable — add default in `profile.toml` or pass `--var` |
| Conditional file always missing | Variable falsey; confirm `type = "confirm"` default / `--var key=true` |
| Docker files missing on fullstack | `use_docker` false |

```bash
forge profiles show my-profile
forge new /tmp/t -p my-profile --no-interactive --dry-run
```

## 11. Relationship to neo-harness

| Concern | Tool |
|---------|------|
| Project layout, docs, CI, governance files | **Forge profile** |
| `jobs/`, `scripts/neo`, harness packs | **`neo init-workspace`** (Forge `--neo auto` can call this) |

Do **not** reimplement neo packs inside Forge templates unless you have a
special case; compose with the neo post-hook instead.
